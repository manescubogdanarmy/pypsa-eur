# Project Directory Structure

Below is an overview of the directories within the PyPSA-Eur Romania project and their roles.

## Core PyPSA-Eur Directories
- **`config/`**: Contains the YAML configuration files that define the parameters, scenarios, and constraints for simulations.
- **`data/`**: Stores raw and pre-processed data required for modeling (e.g., weather data cutouts, power plant capacities, geographic boundaries).
- **`envs/`**: Holds Conda environment configurations (like `environment.yaml`) to ensure reproducible software dependencies.
- **`scripts/`**: The main execution scripts provided by PyPSA-Eur for preparing data, building networks, and solving optimization problems.
- **`rules/`**: Snakemake workflow rules defining the dependencies and execution order of the scripts.
- **`logs/`**: Execution logs generated by Snakemake and internal solvers.
- **`resources/`**: Intermediate processed files and networks (often the output of early Snakemake rules).

## Custom Romania Project Directories (`personal_*`)
- **`personal_analysis/`**: Post-processing scripts for analyzing and interpreting simulation results. Includes generators for adversarial configurations and stress-tests.
- **`personal_dashboard/`**: Contains the interactive visualizations and the `scenario_manager_ui` application for exploring results natively.
- **`personal_data_download/`**: Utilities for downloading heavy external datasets (like ERA5 cutouts and Zenodo archives) necessary for the Romanian scope.
- **`personal_diagnostics/`**: Custom diagnostic scripts and sanity checks (e.g., `check_romania.py`) to validate network topologies and inputs.
- **`personal_runners/`**: Convenience scripts and batch files to quickly launch specific scenarios without manually invoking Snakemake.
- **`personal_tests/`**: Unit tests and validation scripts for custom constraints and cutout implementations (e.g., `test_cutout_implementation.py`).
- **`personal_scratch/`**: Sandbox folder for temporary, one-off, or experimental scripts (e.g., `scratch_update.py`).
- **`personal_docs/`**: Miscellaneous documents and templates that are distinct from the primary documentation vault (e.g., `scenario_template.yaml`, `results_summary.md`).


## Documentation
- **`vault/`**: The consolidated Obsidian knowledge base containing installation, running, usage, architecture documentation, and historical archival logs.
